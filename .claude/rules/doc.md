# Site de documentation

Le fonctionnement du site Symfony de `doc/`. Les règles communes du framework sont dans `CLAUDE.md`.

## Pages

- Ajouter une page : sa ligne dans `doc_sections`, sa méthode, son template.
- **La doc n'a pas de thème** : en-tête, menu, nom du site, accueil sans `.theme-*` (neutral par défaut) ; les couleurs ne sont que dans les démos.
- **Mise en page avec le framework seulement**, pas de CSS en plus (balise native sans classe s'il manque une classe).
- **Chaque composant a sa page, et n'est terminé que quand elle existe** : HTML minimal, variables et comment les changer (défaut, taille, un élément), variantes, tailles, accessibilité, **exemples, contre-exemples et limites**. Les contre-exemples sont en code, jamais affichés (Lighthouse doit rester à 100).
- **Peu de texte, des exemples** (modèle : `components/button.html.twig`) : un exemple = le rendu dans un `.card`, son code juste en dessous, écrit une seule fois (`{% set code %}…{% endset %}` + `{{ include('_example.html.twig', {code: code}) }}` ; `class` change la mise en page du rendu, `html` rend autre chose que le code montré (`{% set demo %}` + `html: demo`, jamais `{% set html %}` : `include` passe toute la page, il resterait pour les exemples suivants) ; code seul : `_code.html.twig`, `language: 'css'` ; filtre `dedent` de `src/Twig/DocExtension.php`). Au plus une phrase avant un exemple, noms de classes en `<code>`, HTML écrit en entier sans boucle Twig (le template = le code affiché), boîtes des démos en classes du framework (`bg-primary-subtle p-2`, `border` pour le parent) ; une aide de `doc.css` (`demo-height`, `demo-glass`) seulement dans le rendu (`html`). Plan : titre + une phrase, exemples, Variables (tableau + CSS commenté), Accessibilité (quelques points), À éviter (`<!-- Non : … -->` / `<!-- Oui -->` dans le code), Limites, Toutes les combinaisons (grille sans code, pour les contrastes).
- Blocs de code : `<pre tabindex="0"><code class="language-html">` (une zone qui défile se prend au clavier). Coloration Prism, doc seulement, en local comme htmx (aucun CDN : ni requête vers un autre site, ni fichier chargé sans empreinte) : `doc/assets/js/prism.min.js`, les `components/prism-*.min.js` du paquet npm `prismjs` 1.30.0 (cœur, markup, css, clike, javascript, scss, bash, dans l'ordre de leurs dépendances), sa licence MIT en tête (obligatoire pour la copier). Un langage de plus : son `prism-<langage>.min.js` à la fin, après ceux qu'il requiert (`components.json`). Les polices sont celles du système : rien à charger.
- Chaque tableau de la doc dans `<div class="table-responsive" role="region" aria-labelledby tabindex="0">`, nommé par sa `<caption>` ou le titre de sa section (`id` sur le `<h2>`) : la doc ne déborde pas à 320px.

## Mise en page

- En-tête, contenu et pied de page : trois `.card glass box-shadow-xl` (`<header>`, `<main>`, `<footer>` dans `base.html.twig`), à 0.75rem l'une de l'autre (l'écart du menu fixé), le contenu en `.card-body p-4 md:p-10`.
- Sur grand écran (lg), la page a la hauteur de l'écran (`lg:h-100svh`), l'en-tête et le pied restent, le `<main>` prend la place qui reste (`flex-grow-1 lg:min-h-0`) et son `.card-body` défile (`position-relative overflow-y-auto` : les `visually-hidden` défilent dedans), `doc.css` rend la place de la barre de la fenêtre (`scrollbar-gutter: auto`) ; sur petit écran et en zoom, toute la page défile (fixes, l'en-tête et le pied cacheraient le contenu, WCAG 1.4.10) ; un élément fixé d'une démo va dans le bloc Twig `fixed`, hors de la carte (`backdrop-filter` en ferait sa référence).
- L'en-tête en `flex-wrap-wrap` (ses boutons passent à la ligne à 320px), une recherche au milieu, entre deux côtés `lg:w-25` en `lg:flex-wrap-nowrap`.
- Recherche : motif « combobox » de l'APG (`<search>`, `<input type="text" role="combobox" enterkeyhint="search">` (`combobox` refusé par le W3C sur `type="search"`), un `.dropdown glass` `role="listbox" popover="manual"` de la largeur du champ par `anchor-size()` dans `doc.css`, une option = un lien `role="option" tabindex="-1"` chargé par htmx) ; clic dans le champ : la liste s'ouvre sans attendre la frappe (toutes les pages si le champ est vide), un deuxième clic la ferme (exemple de l'APG) ; `app.js` filtre sans majuscules ni accents (le début du nom d'abord), le focus reste dans le champ (`aria-activedescendant`, l'option entourée comme au focus), ↓ ↑ en boucle, Entrée, Échap (ferme la liste, puis vide le champ) ; pas de `<datalist>` : sa liste ne prend ni le style ni la largeur du champ.
- Le menu (`_menu.html.twig` : par section un titre en `fs-md fw-bold` sur une bande grise (`bg-neutral-subtle border-radius-md`, pour mieux voir les sections, sans couleur) et une `.list list-borderless`, un trait `border-top` entre deux sections, en `list-sm`) est inclus deux fois : sur grand écran (lg), dans un `<nav class="drawer-start position-fixed glass">` toujours là, le nom du site en haut, la page décalée par `doc.css`, la page en cours centrée par `app.js` ; sur petit écran, dans le drawer en verre (`glass`) du bouton Menu. Il lit `doc_sections` dans `doc/config/packages/twig.yaml` ; le global `colors` sert aux boucles des démos.
- Pied de page, une ligne sur grand écran (il reste affiché) : à gauche le favicon et le nom (lien vers l'accueil) et une phrase (HTML natif, variables CSS, zéro dépendance · licence MIT · codé en duo avec Claude Code) ; à droite « Cette doc est faite avec » htmx et Prism (`btn btn-xs`, ensemble à la ligne sur petit écran), puis GitHub (`btn btn-sm`), arrondis (`border-radius-pill`), sans couleur, avec leur logo (SVG écrits dans `base.html.twig` en `currentColor`, de Simple Icons et du dépôt de Prism).

## doc.css et app.js

- `doc/assets/styles/doc.css` : les aides des démos (dont `.demo-drawer-fixed` : la doc se décale quand le drawer fixé est affiché) et le fond de la doc (comme les fonds d'écran de macOS : quatre bandes de vagues superposées aux teintes de la palette, foncées, pastel en thème clair ; un `<div class="doc-waves">` de `base.html.twig`, hors de `#doc-content`, et ses quatre `<div>`, chacun la crête en `mask-image` répétée et un `translate` en boucle, à sa vitesse et dans son sens).
- `doc/assets/app.js` : le thème (bouton Thème de l'en-tête, qui montre l'emoji du choix et son nom en `visually-hidden`, un `.dropdown` et trois boutons radio avec leur emoji en `aria-hidden` : ☀️ Clair, 🌙 Sombre, 💻 Système ; Système, le défaut, sans `data-theme` : le CSS suit l'ordinateur en direct ; Clair ou Sombre : `data-theme` ; gardé dans `localStorage`, posé avant le CSS par le script du `<head>`), bouton `data-demo-toggle`, bouton `data-demo-toast` (ajoute la copie d'un `<template>` au conteneur), la page en cours au milieu du menu fixé, le bouton Copier de chaque bloc de code (`btn btn-xs` dans le `<pre>`, sans cadre ni changement au survol et au clic (`doc.css`), la coche dit que c'est copié, placé par une enveloppe `position-relative` pour ne pas défiler avec le code ; annonce dans le `#doc-copy-status` de `base.html.twig`).
- Pas de thème Prism : ses couleurs sont dans `doc.css`, celles du fond de la doc (un fond uni, l'indigo clair en thème clair, un peu plus foncé que la page pour se voir sur le verre blanc, l'indigo foncé en sombre ; les mots en `--color-*-emphasis` des vagues primary, secondary, info et accent, ponctuation et commentaires en neutral, commentaires en italique), texte en `--font-size-sm`.

## Navigation et scripts

- **Navigation sans rechargement** : htmx 2 (`doc/assets/js/htmx.min.js`, doc seulement, le framework reste sans dépendance : le `dist/htmx.min.js` du paquet npm `htmx.org`, sa licence 0BSD en tête). Les liens des deux menus, de l'en-tête, du précédent / suivant et de l'accueil (`data-hx-boost`) ne remplacent que `#doc-content` (le `<main>` et le bloc `fixed`, seul gardé pour le bouton Retour) : le menu garde son défilement. Attributs en `data-hx-*` (`hx-*` est refusé par le W3C). Après chaque changement, `app.js` refait ce que faisait le chargement : fermer le drawer du menu, `aria-current` des deux menus, Prism, boutons Copier, conteneurs de toasts, focus sur le `<h1>` (le lecteur d'écran annonce la page ; sans contour dans `doc.css` : pas cliquable, le contour natif de Chromium faisait le tour du texte et du bloc) ; les écouteurs des démos sont sur `document`. Limites : un `{% block stylesheets %}` de page ne se charge pas par htmx ; sur grand écran, Retour remet le main en haut (htmx ne garde que la position de la fenêtre).
- Scripts de `base.html.twig` : `importmap('app')` avant le `<script type="module">` du framework (Firefox ignore une importmap posée après le début du chargement d'un module : plus aucun JS de la doc ; Chromium l'accepte).

## Robots et IA

- `SeoController` + `templates/seo/` : `robots.txt` (tout se lit, l'adresse du sitemap), `sitemap.xml` (l'accueil et les pages de `doc_sections`, sans `lastmod` : une date fausse est pire que rien), `llms.txt` (format de llmstxt.org : la phrase du framework, l'essentiel pour écrire du HTML avec lui, chaque page et sa première phrase) et `llms-full.txt` (toute la doc en Markdown). Tout est calculé depuis `doc_sections` et l'adresse qui répond : aucune adresse écrite en dur, une page ajoutée au menu y entre seule.
- `src/Service/DocPages.php` rend chaque page comme pour un visiteur et convertit le corps de son `<main>` en Markdown (titres, paragraphes, listes, tableaux, blocs de code avec leur langage), sans le rendu des démos (tout `.card`), les contrôles, les images, le `aria-hidden` ni « Toutes les combinaisons ». Il suppose une page = un template sans variable.
- Pas de `noindex` ni de `Disallow`, même pour `/test` et les modèles : Lighthouse SEO tomberait sous 100.
- JSON-LD (schema.org) dans le `<head>` (`_json_ld.html.twig`) : `WebSite` et `SoftwareSourceCode` sur chaque page, `TechArticle` en plus sur une page du menu. `doc_tagline` (`twig.yaml`) : la phrase du framework, pour l'accueil, `llms.txt` et le JSON-LD.
- L'essentiel de `llms.txt` reprend le nommage et le thème de `CLAUDE.md` : changer les deux ensemble.

## Autres pages

- Page de test `doc/templates/test.html.twig` (`/test`) : une page seule (sans `base.html.twig` ni `doc.css`), toute la fenêtre défile ; dialogues (dont deux l'un sur l'autre), drawers des quatre côtés, dropdown, toast, barre collée, bande pleine largeur et bouton fixé, pour vérifier que rien ne bouge au blocage de la page ; on y essaie aussi un exemple avant de le mettre dans sa page.
- **Modèles** (dernière section du menu, `TemplateController`) : des pages entières prêtes à copier (tableau de bord, liste avec filtres, tableau de projet, réglages du compte, connexion, page d'accueil), faites **seulement avec le framework** : pas de `doc.css`, pas de `style`, le JS du site seulement s'il le faut (le toast des réglages). Chacune est un fichier HTML écrit en entier, `templates/templates/pages/<nom>.html.twig` (`/templates/<nom>/page`), dont le seul Twig est l'`asset()` des deux fichiers du framework, montré en `css/webdev-ui.min.css` et `js/webdev-ui.min.js` ; sa page de doc (`templates/templates/<nom>.html.twig`) : une phrase, l'aperçu (`_preview.html.twig` : la page dans un iframe `inert`, réduit de moitié par `.demo-template` de `doc.css`), le bouton qui l'ouvre, « Ce qu'il utilise » (liens vers les composants), le code entier (`_source.html.twig`, `source()`). Contenus inventés et réalistes (Brûlerie Margot, Les Cimes, Studio Ardoise), e-mails en `exemple.fr`. Le `w3c.sh` de `/verifier` les valide avec la doc.
- Accueil : Installer (deux façons, toujours la dernière version : les deux `.min` téléchargés depuis la doc (`download`), ou le projet entier sur GitHub ; pas de tag ni de CDN, le framework change souvent) ; Personnaliser (tout se recalcule dans le navigateur quand on change une variable, sauf les breakpoints : `@use … with` et SCSS à recompiler) ; Ce qu'il y a dedans ; Navigateurs, un tableau simple (logo et nom du navigateur, version minimum), pas le détail par fonction (décidé) ; dessous, ce qui n'est qu'un plus (l'accordéon animé dans Chromium seulement, faute d'`interpolate-size` ; dialogues et drawers animés partout, mesuré dans Firefox et WebKit) et « Réduire les animations », qui coupe tout. Versions d'après web-features (les données Baseline de MDN) ; Opera, Brave et Samsung Internet : la première version avec Chromium 135 ou plus (données MDN, journal de Brave). Logos de `@browser-logos` dans `doc/assets/images/browsers/`. À mettre à jour quand une fonction indispensable plus récente entre dans le framework. Le `README.md` en reprend l'essentiel (principes, installer, personnaliser) : changer les deux ensemble.
