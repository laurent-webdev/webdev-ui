# Composants faits

Les choix de chaque composant : le HTML attendu, ce qui le distingue, le pourquoi d'un choix inhabituel. Le détail est dans son SCSS et sa page de doc ; les règles communes (thème, focus, tailles, ordre du fichier) sont dans `CLAUDE.md`. Un choix « décidé » ou « écarté » ne se repropose pas.

- **button** : `<a>` pour aller vers une page, `<button>` pour une action, mêmes styles calculés. Tailles 24, 31, 36, 41px (padding 2, 4, 5, 6px en haut, 8, 10, 12, 16px sur les côtés) ; les champs, la pagination, la navbar et `btn-close` suivent. Pas de taille responsive.
- **link** : `<a class="link theme-*">` ; un `<a>` sans classe reste natif. Sans thème, la couleur du texte autour. Survol et clic : soulignement 2× puis 3× plus épais. Focus `currentColor`.
- **spinner** : cercle en CSS, `currentColor` (pas de `.theme-*`), en `em`. Toujours un texte dans un `role="status" aria-live="polite"` présent avant le spinner.
- **badge** : suit le texte (`max(--font-size-xs, 0.75em)`), pas de tailles, pas interactif (une étiquette cliquable est un bouton).
- **alert** : message dans la page, sans JS, un bloc. Pas de `role` au chargement ; affiché par JS : zone présente dès le chargement, `role="status" aria-live="polite"` ou `role="alert"` seul pour une erreur urgente. Le texte dit le type (WCAG 1.4.1).
- **accordion** : `<div class="accordion-*">` + `<details name>` + `<summary>` + `.accordion-body`, sans JS ni `aria-expanded`. `height: fit-content`. Tailles : le padding des côtés du bouton de la même taille, tout autour, titre et contenu ensemble (titres de 34, 41, 48, 59px) ; pas sur la hauteur des boutons : rien ne s'aligne à côté, et le contenu serait trop serré. Ouverture animée par `::details-content` + `interpolate-size` (Chrome et Edge seulement, ailleurs d'un coup). Flèche en bordures `currentColor` (visible en contraste élevé).
- **card** : `.card-header` / `-body` / `-footer`, `<img>` directement dedans. La variante colore toute la carte ; texte de la page sur subtle et outline. Flex en colonne : hauteurs égales dans une grille. Coins des enfants : `calc(rayon - bordure)`.
- **dialog** : `<dialog>` natif avec ses propres classes (pas celles de la carte), `.dialog-header` / `-body` / `-footer` en `<div>` (pas `<header>` / `<footer>`). Ouvert et fermé sans JS (`command` / `commandfor`, `closedby`, `<form method="dialog">`). Tailles `xs` à `xl` = largeur du breakpoint. Page bloquée par `:root:has(dialog:modal)` + `scrollbar-gutter: stable` dans le reset. Dans Firefox, le fondu et l'agrandissement à l'ouverture se voient à peine (le fond et le drawer s'animent bien) : gardé tel quel (décidé).
- **btn-close** : le carré est le bouton, la croix un `mask-image` sur `::before` en `currentColor`, un trait de 2px à toutes les tailles (`vector-effect='non-scaling-stroke'`). Variantes solid, subtle et outline, désactivé comme le bouton, 24px par défaut (= xs), côté `--btn-close-width`. `aria-label="Fermer"`.
- **drawer** : un `<dialog>` modal, le côté est la variante (`drawer-start`, `-end`, `-top`, `-bottom`), écart `--drawer-inset`. Pas encore de thème ni de variantes de couleur. Toujours là : `drawer-start` / `-end` sur un `<aside>` ou un `<nav>` (pas un `<dialog>` : il garderait le rôle dialog, comme la navbar), collé (`sticky`, une colonne à côté du contenu) ou, avec l'utilitaire `position-fixed`, contre le bord de l'écran aux écarts du drawer (menu de côté ; le site décale sa page lui-même), toute la hauteur de l'écran ; sur petit écran, `d-none md:d-block` et le même contenu dans un vrai drawer.
- **dialog.ts** : fermeture animée des `<dialog data-dialog>` (dialogues et drawers) : annule `cancel` et `command="close"`, pose `data-closing`, appelle `close()` à la fin des animations. Et `closedby="any"` là où le navigateur ne le connaît pas (Safari), pour tout dialogue modal, avec ou sans `data-dialog` : appui et relâché sur le fond d'un dialogue modal (hors de son cadre) → `requestClose()`, animé comme Échap ; `pointerdown` / `pointerup`, pas `click` (sur iPhone, un `click` écouté sur `document` n'arrive pas toujours). Solutions d'attente (voir « En attente »).
- **fieldset** : `<fieldset class="fieldset">` + `<legend>` : le cadre gris (`--border-color`) et arrondi des cartes à la place du trait natif en relief, rien d'autre ; avec `.form-field` pour empiler les cases. Le `<legend>` reste natif, sur le trait. Pas de thème ni de tailles. Sans la classe, le cadre natif reste (le reset ne change pas le visuel) ; `border-0 p-0` l'enlève.
- **dropdown** : `popover` + `popovertarget` + positionnement par ancre, sans JS. En `position: absolute` : il défile avec la page (en `fixed`, recalé sur le bouton à chaque image, il traînait derrière au défilement sur iPhone) ; ses replis se testent contre la page, pas l'écran : il ne s'ouvre au-dessus qu'en bas de la page. Pas de classes de côté (`-top`, `-start`, `-end`) : il se place seul là où il a la place (décidé). Pas de `role="menu"` ni d'`aria-expanded` écrit (motif « disclosure »). `.dropdown-item` sur `<a>` ou `<button>`, seul le fond change. Pas de variantes : neutral dans son `:root`.
- **list** : `<ul class="list">` + `<li>` sans classe (le padding) ; `.list-item` sur le `<a>` ou le `<button>` d'un `<li>`, qui prend le padding par `:has()` (toute la ligne se clique). Comme le dropdown : seul le fond change, pas de variantes (`list-subtle` / `-solid` essayées comme la pagination, écartées), neutral dans son `:root`. Tailles `-xs` à `-lg` (padding, texte et interligne ; padding vertical 4, 6, 8, 10px, lignes de 26, 33, 40, 47px ; `md` = le défaut ; pas sur la hauteur des boutons : une liste ne s'aligne pas à côté d'un bouton). Puces retirées par `list-style-type: ""` (avec `none`, Safari n'annonce plus la liste ; `role="list"` = warning W3C). `height: fit-content` comme l'accordéon. Option `.list-borderless` (comme `table-borderless`) : `--list-border-width: 0px`, et chaque `<li>` prend les coins de la liste (sinon le fond d'un élément du milieu serait carré). `.list-unstyled`, seule (liens d'un pied de page, étiquettes) : le retrait à 0 et le `list-style-type: ""` de `.list`, dans le même sélecteur, rien d'autre ; dans `_list.scss` et sa page, pas un utilitaire (son nom est celui d'une variante).
- **tab** + **tab.ts** : motif « Tabs » de l'APG, `<div class="tab" role="tablist" data-tab>` + `<button class="tab-item" role="tab">`, panneaux `role="tabpanel"` sans classe. L'état de départ est dans le HTML (`aria-selected`, `tabindex="-1"`, `hidden`), le JS ne fait que le changer (pas de MutationObserver) : sans JS, seul le premier panneau se voit. Activation automatique, ← → Début Fin, `tab-beforechange` / `tab-change` sur la rangée. Rangée en `overflow-x: auto` (pas de passage à la ligne). Vertical par `aria-orientation="vertical"` (demandé par l'ARIA, lu par le CSS, pas de classe), ↑ ↓ en plus, à gauche du panneau par la grille. Pas de variantes ni de tailles.
- **table** : `<table class="table">` + `<caption>` et `<th scope>`, les autres balises sans classe ; un trait `--border-color` sous chaque ligne, cellules en haut, `th` et `caption` alignés comme le texte, `tabular-nums`, `height: fit-content` comme la liste. Pas de variantes : `.theme-*` directement sur `.table` (comme `.link`), fond `-subtle`, traits `-subtle-border`, texte de la page ; sans thème, fond transparent et `--border-color` (repli dans le `var()`). Options ajoutées à `.table` et combinables : `-striped` et `-hover` (le fond léger mélangé à la couleur à `--state-mix-soft` / `-strong`, neutral sans thème), `-bordered`, `-borderless` (`--table-border-width: 0px`). Tailles `-sm` / `-md` / `-lg`, padding seul (texte par `fs-*`). Trop large : `<div class="table-responsive" role="region" aria-labelledby tabindex="0">` (`overflow-x: auto` + `position: relative` : sinon les `visually-hidden` du tableau, en `absolute`, ne défilent pas avec lui et élargissent la page ; le nom de Bootstrap), jamais `display: block` sur la table (sa structure se perd).
- **navbar** : `<nav class="navbar md:navbar-expand">` + `.navbar-brand`, une `.navbar-list` dans la barre et la même dans un `.drawer-*` ouvert par `<button class="btn navbar-toggle" command="show-modal">`. Deux listes, pas un `<dialog>` affiché dans la barre comme Bootstrap 6 : il garderait le rôle dialog sur ordinateur et demanderait d'annuler tout le style du drawer. `navbar-expand` (+ `sm:` … `2xl:`) choisit la liste qui se montre ; `.navbar-item` suit la règle des listes d'éléments ; 36px de haut avec un cadre transparent, comme `.pagination-item` (la hauteur d'un bouton à côté, un cadre visible en contraste élevé). `.navbar-toggle` ajoute les trois traits (`mask-image`, trait de 0.125em comme les flèches) à un bouton du framework. Variantes `.navbar-subtle` / `-solid` : fond, `--navbar-padding-inline`, états des liens un cran plus forts (comme le bouton subtle et solid), focus `currentColor` sur solid ; seulement la liste de la barre (`> .navbar-list`), le drawer garde la page. Sans thème, neutral (le `:root` des listes d'éléments). Bande sur toute la largeur du parent, pas de `.container` à l'intérieur.
- **pagination** : `<nav aria-label>` + `<ul class="pagination">` + `<a class="pagination-item">` (ou `<button>`), `<li>` sans classe, `<li>…</li>` pour les points de suspension. Sans cadre (transparent : hauteur d'un bouton, visible en contraste élevé). `.pagination` sans couleur : texte de la page, survol en voile gris, page en cours au voile du clic. `.pagination-subtle` et `-solid` + `.theme-*` : texte en emphasis comme `btn-text` (survol `-subtle`, clic renforcé + emphasis forte) ; page en cours au fond du clic + emphasis forte (subtle, un cran au-dessus du survol) ou fond plein + `-contrast` (solid). Focus comme les boutons. Désactivé : `<a>` sans `href` ou `<button disabled>`. Carré pour un chiffre (`min-inline-size` en `1lh`). Option `.pagination-group` : éléments collés, cadre gris partagé (marge négative), coins aux deux bouts, au survol et sur la page en cours, cadre de la couleur du thème (`--color-neutral` sans couleur), devant les voisins. Tailles `-sm` / `-md` / `-lg` (31, 36, 41px), côtés du bouton de la taille en dessous (un chiffre reste carré).
- **toast** : une pile, plusieurs à la fois. `<div class="toast-container" role="status" aria-live="polite" aria-atomic="false" popover="manual" data-toast>` vide au chargement, en bas côté fin, ouvert par `toast.ts` : dans le top layer, au-dessus de tout ce qui est positionné, sans `z-index` (pas de `display` écrit sur le conteneur : il afficherait le popover fermé, écart en marges) ; le site y ajoute un `.toast` / `-solid` / `-subtle` / `-outline` + `.theme-*` (comme l'alerte, fond `--color-background` : il passe sur la page), un texte et une croix `data-toast-close`. Options combinables `.toast-container-top` et `-start` (comme le drawer) ; en haut, le dernier arrivé sous les autres (l'ordre du HTML, pas de `column-reverse`). Minuteur en CSS (`animation-delay: var(--toast-duration)`, en pause au survol et au focus ; aucun sur un toast qui contient un lien ou un autre bouton que la croix, par `:has()`, WCAG 2.2.1) : le JS n'a pas à savoir qu'un toast arrive, sans `MutationObserver` ; le reset ne réduit que la durée, le délai reste. `toast.ts` retire le toast à la fin de `toast-hide` ou du fondu de la croix (`data-closing`). Un dialogue modal ouvert après passe devant : le dialogue a son conteneur dans son `.dialog-body`, sans `popover` (il est déjà dans le top layer).
- **form**, en refonte ; tout le reste garde le natif :
    - `.form-input` / `-sm` / `-md` / `-lg` (chaque taille s'utilise seule) : toute la largeur du parent (`width: 100%`, comme Bootstrap : la largeur native déborde à 320px ; `w-auto` la rend), padding, texte et interligne de la taille (comme le bouton), fond `--color-background`, arrondi ; cadre `--form-input-border-color`, celui du thème avec un `.theme-*` ; focus comme les boutons ; survol natif ; désactivé estompé comme les boutons (notre fond, notre cadre et le `color: inherit` du reset effacent l'aspect natif). En erreur, `[aria-invalid="true"]` pose les tokens du thème danger (cadre 2,43:1 en clair, accepté : le message dit l'erreur) ; message en utilitaires (`fs-sm color-danger-emphasis`), pas de classe. Pas de `:user-invalid` : cadre rouge sans message en texte (WCAG 1.4.1). Champ fichier : bouton collé au cadre et coupé par lui (`overflow: hidden` : il dépassait sur iPhone), comme `btn-solid` sur `:enabled`, `ButtonFace` / `ButtonText` sans thème. Dates et heures : `appearance: none` (sur iPhone, l'aspect natif repasse le champ en `content-box` avec une largeur minimum : il dépasse de son parent, bug WebKit 301648), valeur au début et une ligne de haut même vide ; le padding de `::-webkit-datetime-edit` et de son `-fields-wrapper` à 0 : 31, 36, 41px comme les autres champs. Liste sans `multiple` ni `size` : `appearance: none` et une flèche SVG grise `#808080` (une pour les deux thèmes, `right` physique) à `--form-input-padding-inline` du bord, la flèche native de Chromium collant au cadre.
    - `.form-range`, `.form-checkbox`, `.form-radio` : le dessin natif coloré par `accent-color` (tokens `--form-theme-*`, un seul jeu pour tout le formulaire : champs, switch, cases) ; focus comme les boutons, autour du range entier (un contour sur le rond seul demanderait de redessiner le range : le natif est gardé).
    - `.form-field` : libellé, champ et message en flex colonne ; `> label`, cases et boutons radio en `align-self: start` (pas cliquables sur toute la ligne) ; sur un `<fieldset>`, il empile les cases.
    - `.form-input-group` : un champ, des boutons du framework et des `.form-input-group-text` (@, €, https://) collés sur une ligne, comme `pagination-group` (marge négative, coins aux deux bouts) ; le champ prend la place qui reste ; sur la ligne partagée, le plus coloré devant : boutons solid, outline et subtle devant le champ, le champ devant les textes et `.btn`, le champ en erreur devant tout, le focus encore devant ; la taille par `.form-sm` / `-md` / `-lg` sur le groupe, pas sur le champ. Pas `.form-group` : c'est le nom de notre `.form-field` dans Bootstrap 6.
    - `.form-sm` / `-md` / `-lg` sur un groupe : tout ce qu'il contient, les contrôles natifs par `zoom`.
    - Switch sur `<input type="checkbox" role="switch">`, sans JS, sur le modèle du bouton : `.form-switch` sans couleur (allumé : `currentColor`) et `.form-switch-solid` + `.theme-*` (allumé : fond de la couleur, cadre `-border`, curseur `-contrast`) ; éteint, tous : cadre `--form-input-border-color`, curseur `currentColor`. Focus comme les boutons, aussi sur `.form-switch`. Centré sur les capitales de son libellé (`vertical-align: calc(0.5cap - hauteur / 2)` ; `middle` le mettait 1,5px trop bas). Tailles `.form-switch-sm` / `-md` / `-lg`, combinables.
    - Écartés, à ne pas reproposer : `.form-switch-subtle` ; un curseur coloré (emphasis ou couleur du thème, allumé comme éteint) ; le rebond du curseur.

## En attente

- **Fermeture animée en CSS seul** le jour où `overlay` sera dans Firefox et Safari : supprimer `dialog.ts`. D'ici là, Échap pressé deux fois ferme d'un coup, et un `preventDefault()` du site sur `cancel` est sans effet (un événement `dialog-beforeclose` annulable réglerait ça).
- **`closedby` dans Safari** (Technology Preview depuis avril 2026) : retirer de `dialog.ts` le clic à côté (`onPointerDown`, `onPointerUp`, `outsideDialog`). D'ici là, `closedby="none"` y est ignoré (Échap ferme).
- **Liste** : `list-style-type: ""` garde la liste dans Safari d'après un test de 2023 (Matuzović, Safari 16.5) repris par Bootstrap 6, pas par MDN : à vérifier avec VoiceOver.
- **Formulaire** : Safari pas testé (flèche des listes, champ fichier, switch, zoom des cases) ; Firefox : focus et thème sombre des cases et des radios pas vus ; en clair, les couleurs pleines (switch allumé, cases, range, cadre des champs) sont sous 3:1 sur le fond de page (choix assumé, dit dans la doc) ; le cadre gris des champs l'est aussi en sombre (2,13:1).
